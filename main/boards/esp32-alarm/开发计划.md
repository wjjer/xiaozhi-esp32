# ESP32-Alarm 开发计划

## 1. 计划目标

`esp32-alarm` 的开发目标是基于 `xiaozhi-esp32` 现有框架，落地一台可量产演进的儿童 AI 学习陪伴闹钟。

计划分成两层：

- `软件目标`：复用现有主流程、网络、音频、设备状态框架，快速形成产品闭环
- `产品目标`：实现一台可长期摆放在床头和书桌上的儿童桌面终端

## 2. 技术路线

### 2.1 总体路线

- 主控：`ESP32-S3`
- SDK：`ESP-IDF`
- UI：`GUI Guider v1.9.0 + LVGL v9 + esp_lvgl_port + esp_lcd`
- 联网：`Wi-Fi + ML307C`
- 语音：复用现有 xiaozhi 语音能力

### 2.2 为什么复用现有框架

当前仓库已经具备：

- 应用主流程
- 音频服务
- 网络接入
- 设备状态机
- 显示抽象
- 双网络板级能力

所以 `esp32-alarm` 不需要从零搭建 AI 终端底座，而是重点投入在：

- 板级适配
- 产品功能
- UI 和交互
- 时间管理与学习模块

### 2.3 新板子目标

`esp32-alarm` 需要承载：

- 图形化 UI
- 触摸与语音交互
- 闹钟与提醒
- 学习类占位和后续内容接入
- 网络与状态展示

## 3. 功能拆分

### 3.1 时间管理域

这是第一优先级。

包含：

- 闹钟列表
- 新建闹钟
- 编辑闹钟
- 响铃页
- 倒计时
- 秒表
- 专注时间
- 夜灯

要求：

- 本地可用
- 响应简单直接
- 支持后续语音控制

### 3.2 AI 交互域

这是核心交互层。

包含：

- AI 问答
- 闲聊陪伴
- 讲故事
- 生活提醒
- 语音控制设备能力

要求：

- 支持唤醒、聆听、思考、回答状态
- 响应优先于复杂推理
- 失败时可降级提示

### 3.3 学习辅助域

这是第二价值层。

包含：

- 学习园地
- 英语查词
- 生词本
- 背单词
- K12

说明：

- 首版先做页面占位
- 后续再接内容源与课程体系
- 不让内容平台阻塞产品主线

### 3.4 家庭连接域

包含：

- 家长录音提醒
- 远程提醒
- 轻量语聊
- 夜间陪伴

## 4. UI 开发策略

### 4.1 GUI Guider 优先策略

`esp32-alarm` 的 UI 开发方式调整为 GUI Guider 方案：

- `ui_designer/alarm/alarm.guiguider` 是唯一 UI 布局源工程
- `ui_generated/` 是 GUI Guider 导出代码目录
- 固件侧不再新增手写 LVGL 页面布局
- `main/ui/` 只负责业务状态、数据更新和页面路由
- `lcd_display` 只负责初始化、页面切换和生成控件映射

当前 GUI Guider 工程已经可运行；下一阶段重点是把固件当前手写 LVGL UI 迁移到 GUI Guider 导出物。

### 4.2 结构策略

UI 仍采用四层产品结构，但布局实现全部由 GUI Guider 完成：

- `系统层`：启动、待机、状态栏、通知、弹窗、语音浮层
- `桌面层`：首页、应用网格
- `功能层`：AI、闹钟、学习、工具
- `内容层`：查词、生词本、背单词、K12 等占位内容

### 4.3 页面开发顺序

1. GUI Guider 工程完成启动页、首页、应用网格、AI、学习页
2. GUI Guider 工程完成闹钟、天气、倒计时、秒表、专注、夜灯页
3. 导出 `ui_generated/` 并接入固件显示适配层
4. 将首页、AI、学习页状态更新映射到生成控件
5. 删除或隔离旧手写 LVGL 页面
6. 学习内容和闹钟完整业务后续接入

### 4.4 学习内容接入策略

以下模块首版仅做占位：

- 英语查词
- 生词本
- 背单词
- K12

占位内容应满足：

- 有入口
- 有页面
- 有说明
- 便于后续替换真实内容源

## 5. 分阶段计划

### 5.1 P0

- `esp32-alarm` 板级适配

- 首页和应用网格

- 倒计时 / 秒表 / 专注时间
- 语音与触摸的基础交互

### 5.2 P1

- 闹钟列表与新建编辑
- 响铃页与贪睡逻辑
- 天气展示
- 家长录音提醒
- 学习类占位页完善

### 5.3 P2

- 英语查词真实接入
- 生词本真实接入
- 背单词真实接入
- K12 内容接入
- 第三方内容入口
- 更丰富的家庭提醒能力

## 6. 代码组织建议

- 板级代码放在 `main/boards/esp32-alarm/`
- UI 系统只在 `esp32-alarm` 板编译
- 学习内容页先保留抽象层，不强耦合具体内容源
- 闹钟、计时、专注独立成业务模块

## 7. 关键原则

- `高频、低门槛、稳定可用`
- `离线时间能力 + 在线 AI 能力`
- `按钮可闭环`
- `学习内容先占位，后接入`
- `不让内容源阻塞产品交付`

## 8. 项目结论

这个项目适合按“先桌面系统、再业务闭环、最后内容增强”的方式推进。

只要先把 `闹钟、AI、学习入口、基础工具、状态系统` 做完整，就已经具备一版可交付产品的核心形态；学习内容中的真实数据接入可以作为后续增强项单独推进。

## 9. P0 研发开工包

### 9.1 P0 开发任务清单

#### 9.1.1 板级与硬件打底

- 完成 `esp32-alarm` 板级注册、宏定义和默认配置
- 跑通 LCD、背光、触摸、音频、Wi-Fi、ML307C 初始化
- 确认设备上电、显示、网络、输入都能稳定起来

交付物：

- 板级可编译
- 设备可点亮
- 网络状态可上报
- 触摸可接入 UI

#### 9.1.2 UI 系统骨架

- 首页、应用网格、AI、学习、闹钟、工具六个主入口打通
- 状态栏、通知层、弹窗、AI 浮层建立
- 首页默认落地显示时间、状态、高频入口

交付物：

- 可从首页进入各主模块
- 可返回首页
- 状态栏常驻

#### 9.1.3 闹钟与时间管理

- 闹钟列表页
- 新建闹钟页
- 编辑闹钟页
- 响铃页
- 倒计时页
- 秒表页
- 专注时间页
- 夜灯页

交付物：

- 闹钟能够创建、保存、列表展示
- 倒计时、秒表、专注时间能独立使用
- 响铃页可抢占显示

#### 9.1.4 AI 交互闭环

- AI 聆听、思考、回答三态
- 语音入口与首页/应用页联动
- AI 响应失败时可降级提示

交付物：

- 语音入口可触发
- AI 状态可见
- 会话结束可返回来源页

#### 9.1.5 学习入口占位

- 学习首页
- 英语查词占位页
- 生词本占位页
- 背单词占位页
- K12 占位页

交付物：

- 学习域入口完整
- 内容页能打开、能返回
- 后续接内容源时不改信息架构

#### 9.1.6 基础工具

- 天气页
- 倒计时页
- 秒表页
- 专注时间页
- 夜灯页

交付物：

- 工具类页面完整
- 能从应用网格进入
- 能回到首页或网格页

### 9.2 P0 接口清单

#### 9.2.1 板级初始化接口

- `Board::GetDisplay()`
- `Board::GetBacklight()`
- `Board::GetAudioCodec()`
- `Board::GetLed()`
- `Board::GetNetworkType()`
- `SetNetworkEventCallback(...)`

说明：

- 用于板级与系统服务的基础连接
- 负责显示、背光、音频、网络、LED 的初始化入口

#### 9.2.2 显示与 UI 接口

- `SetupHomeScreen()`
- `SetupAppGridScreen()`
- `SetupPlaceholderScreen(title, description)`
- `SetupAiScreen()`
- `SetupStudyScreen()`
- `SetupAlarmScreen()`
- `SetupWeatherScreen()`
- `SetupTimerScreen()`
- `SetupStopwatchScreen()`
- `SetupFocusScreen()`
- `SetHomeTime(time_text)`
- `SetHomeStatus(status_text)`
- `AttachTouchHandle(touch_handle)`
- `SetStatus(...)`
- `ShowNotification(...)`

说明：

- 这些接口只在 `esp32-alarm` 板启用的新 UI 中使用
- `SetHomeTime` 和 `SetHomeStatus` 属于首页状态刷新接口
- `AttachTouchHandle` 负责把触摸接入 LVGL

#### 9.2.3 UI 路由接口

- `UiSystem::Initialize()`
- `UiSystem::SetState(state)`
- `UiSystem::SetHomeStatus(status)`
- `UiRouter::NavigateTo(route)`

说明：

- 用于页面状态和页面跳转
- `home / app_grid / ai / study / alarm / weather / timer / stopwatch / focus` 是 P0 需要支持的基础路由

#### 9.2.4 网络状态接口

- `NetworkEvent::Scanning`
- `NetworkEvent::Connecting`
- `NetworkEvent::Connected`
- `NetworkEvent::Disconnected`
- `NetworkEvent::WifiConfigModeEnter`
- `NetworkEvent::WifiConfigModeExit`
- `NetworkEvent::ModemDetecting`
- `NetworkEvent::ModemErrorNoSim`
- `NetworkEvent::ModemErrorRegDenied`
- `NetworkEvent::ModemErrorInitFailed`
- `NetworkEvent::ModemErrorTimeout`

说明：

- 这些事件用于驱动状态栏和首页提示
- P0 需保证 Wi-Fi / ML307C 的状态反馈完整

#### 9.2.5 时间管理接口

- 闹钟数据保存 / 读取
- 闹钟创建 / 修改 / 删除
- 响铃启动 / 停止 / 贪睡
- 倒计时启动 / 暂停 / 清零
- 秒表启动 / 暂停 / 清零
- 专注时段启动 / 结束

说明：

- P0 可以先用本地实现
- 接口优先保证闭环，再考虑云同步

#### 9.2.6 AI 交互接口

- 语音唤醒
- 开始聆听
- 结束聆听
- 思考态展示
- 回答态展示
- 失败态提示

说明：

- P0 先保证 UI 可见、流程可闭环
- 复杂对话能力后续增强
